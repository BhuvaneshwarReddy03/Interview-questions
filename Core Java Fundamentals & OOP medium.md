## Can a class extend more than one class?
No, Java does not support multiple inheritance with classes to avoid the Diamond Problem.
If two parent classes have the exact same method signature or instance state, the compiler faces ambiguity over which method implementation to inherit or which parent constructor/fields to initialize. To keep the language simple and avoid this ambiguity, Java restricts classes to single inheritance, while allowing multiple inheritance of type through interfaces.

## What is the diamond problem, and how does Java handle it?
A diamond problem occurs in multiple inheritance when a child class tries to extend two parent classes through multiple inheritance. If we have two identical methods in both parent classes, this leads to ambiguity because the compiler gets confused about which method it has to call. To prevent this, Java does not support multiple inheritance with classes.
Coming to interfaces, a class can implement multiple interfaces. If both interfaces have the same default methods, the class is forced to override the default method. It can provide its own behavior, or it can explicitly specify which interface method it wants to call using InterfaceName.super.method().

## Explain Method Overloading vs Method Overriding. Can we override static methods? Can we override private methods?
Method overloading is declaring methods in the same class with the same name but different parameter types or counts.
Method overriding is declaring a method in a child class with the exact same name, return type, and parameters as in the parent class.
We cannot override static methods. Method overriding relies on dynamic method dispatch based on the runtime object instance on the Heap. Static methods belong to the class rather than an object, so resolution happens at compile time based on the reference type. If a subclass declares the same static method, it is called method hiding, not overriding.
We cannot override private methods because their visibility is restricted to the declaring class. They are not visible or inherited by subclasses, so any identical method defined in the child class is treated as an entirely separate, new method.

## What is method hiding vs method overriding?
Method hiding applies to static methods, and method overriding applies to instance methods. The thing is, whenever we declare two static methods in parent and child class with the same exact name and parameters, it hides the parent method. The which method executes is decided on the compile time based on the reference type. Method overriding, when a which method gets called in method overriding is dependent on the object type living on the heap.

## What is static vs dynamic binding?
Static binding occurs at compile time and dynamic binding occurs at runtime. Compiler resolves which method to call based on the Reference type. It applies to static methods, private methods, and final methods, and also method overloading because these methods cannot be overridden. And coming to dynamic binding, JVM resolves which method to call based on the object type, actual object instance. This is used for method overriding.

## What is constructor overloading?
Constructor overloading is defining multiple constructors within the same class with different parameter lists (different types, counts, or order).
It allows us to initialize objects in different states depending on the available data. To avoid code duplication between overloaded constructors, we use constructor chaining with the this(...) keyword to delegate common initialization logic to another constructor.

## hat is the difference between a constructor and a method? Can a constructor be private? Why can't constructors be inherited?
A constructor is used to initialize the state of an object, has no return type, and must match the class name. A method defines the behavior of an object, must declare a return type (or void), and can have any name.
A constructor can be private. We use private constructors in Singleton patterns to control instance creation, or in utility classes containing only static methods to prevent instantiation altogether.
Constructors cannot be inherited because a constructor must match the name of the declaring class, and its sole purpose is to initialize the state specific to that class. A subclass does not inherit parent constructors; it simply delegates parent initialization using super().

## What is composition, and how is it different from inheritance?
Inheritance and composition are the ways to promote code reuse, and the main difference actually is how they handle the tight coupling and flexibility. Inheritance represents is a relationship. Basically, child class is tightly coupled to parent class at compile time. If something changes in the parent class, this might break the child class, and we cannot change the behavior on the execution during the execution time. Coming to composition, composition represents has a relationship. In this, basically a class holds the reference to an instance of another class and uses the methods of those instances. This provides loosely coupling basically. We can change the behavior at runtime using dependency injection. Basically, there is one thing, one size suggestion for one suggestion for design principle, we should give preference to composition over inheritance when we want to promote the code reuse. It prevents tight coupling and it's basically flexible.

## What is association, aggregation, and composition?
These three represent relationships between classes, but they differ in storage, ownership, and lifecycle. In association, the class never stores the dependency object as a reference. It simply takes the object as a method parameter, uses it, and finishes, so destroying the class object does not affect the dependency object. In aggregation, which is a weak has-a relationship, the class stores the object reference and uses it, but the child object is created outside and injected. When the main class object gets destroyed, the dependency object does not get destroyed because its lifecycle is independent. In composition, which is a strong has-a relationship, the class creates the dependency object directly and uses it. Whenever this class object gets destroyed, the dependency object gets destroyed too because its lifecycle completely depends on the class object.

## Explain Covariant Return Types in Java.
Covariant return type means when a child class overrides a method, it can return a subtype of the parent class method's return type instead of the exact same type. We need it because the caller does not have to explicitly typecast the returned object, which avoids class cast issues and makes the code much cleaner.

## What is the difference between pass-by-value and pass-by-reference? How does Java handle object references?
Pass by value means passing a copy of the actual value into the method parameter, while pass by reference means passing the memory address of the original variable directly. Java is strictly pass by value and never pass by reference. When we pass an object, Java makes a copy of the reference variable containing the memory address and passes that copied reference into the method parameter. Because both the original reference and the copied parameter reference point to the same object in the heap, modifying the object's fields inside the method affects the original object. However, if we assign a new object to that method parameter reference, it only reassigns the local copy, so the original reference outside remains completely unchanged.

## What is a Marker Interface? Give examples (Serializable, Cloneable). How do they work internally?
A marker interface is an empty interface with no methods or fields, used to tag a class for special treatment. Under the hood, Java uses the instanceof check to verify if the object implements the marker interface. For example, Serializable tags a class so that ObjectOutputStream knows it is safe to serialize; if it is not tagged, it throws NotSerializableException. Similarly, Cloneable tells the JVM that calling clone() is permitted; without it, CloneNotSupportedException is thrown.
